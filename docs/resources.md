<h2 align="center">🌐 Resources</h2>

**Resources** and **[Modules](modules.md)** are the two parts that compose your system in GoForge. A resource is a technical capability — an HTTP server, a database, a cache — added to a project on demand.

```bash
goforge add <resource>
```

---

<h2 align="center">📦 Status</h2>

<div align="center">

| Resource | Description | Status |
|---|---|:---:|
| 🌐 **http** | HTTP server, routes, optional middlewares (CORS, rate limiter, secure headers), optional WebSocket support | ✅ |
| 🗄️ **mysql** | Database connection and configuration | ✅ |
| 🐘 **sqlite / postgresql** | Additional database options | 💬 coming with v1 |
| ⚡ **redis** | Caching | 🚧 template in progress |
| 🐇 **rabbitmq** | Messaging | 🚧 template in progress |
| 🐳 **docker** | Containerization based on the project's resources | 🚧 template in progress |

</div>

`http` asks a short interactive setup (middlewares, WebSocket, hub); `mysql` needs no input. Both are recorded under `resources:` in `blueprint.yaml` and generated by `goforge setup`.

---

Adding a resource never requires touching GoForge's core generation workflow — each one is self-contained, which is what lets new resources land independently. See [Roadmap](roadmap.md) for what's next.
